## ⚠️ Clinical Coordination & Scope Notice
**BloodBridge is strictly an emergency coordination platform.**  
It is **NOT** a medical diagnosis authority, medical eligibility assessor, or a replacement for accredited hospitals and clinical blood banks. Blood compatibility scores generated by the platform serve exclusively for logistical prioritization. Pre-donation health screening, infectious disease testing, and serological cross-matching must always be performed in person by qualified medical personnel prior to any transfusion.

---

## 1. Problem Statement
During acute blood emergencies, patient families are forced to navigate fragmented WhatsApp groups, frantic phone calls, social media pleas, and outdated donor contact sheets. This ad-hoc approach creates severe vulnerabilities:
- **Critical Time Delays**: Hours spent manually verifying if potential donors are nearby, available, or compatible.
- **Alarm Fatigue & Spam**: Uncontrolled broadcasts overwhelm donors with outdated or already-fulfilled requests.
- **Duplicate Chaos**: Multiple family members post overlapping requests for the same patient at the same hospital.
- **Zero Real-Time Tracking**: Requesters have no visibility into whether anyone has accepted or is en route to the hospital.
- **Privacy Exposure**: Patient phone numbers, hospital wards, and personal medical details are broadcasted to uncontrolled public groups.

---

## 2. The BloodBridge Solution
BloodBridge replaces unstructured noise with an end-to-end, hospital-verified coordination pipeline:

```
[ EMERGENCY REQUEST ] (Family / Attendant creates request with duplicate check)
        │
        ▼
[ HOSPITAL VERIFICATION ] (Staff confirms patient admission & genuine urgency)
        │
        ▼
[ SMART DONOR MATCHING ] (ABO/Rh matrix + Haversine distance + Reliability score)
        │
        ▼
[ REAL-TIME NOTIFICATION ] (WebSocket push to matched nearby available donors)
        │
        ▼
[ ACCEPT / DECLINE ] (Donor commits in 1 click; status updates in real time)
        │
        ▼
[ MULTI-STAGE ESCALATION ] (Auto-expands search: 3 km → 7 km → 15 km if needed)
        │
        ▼
[ HOSPITAL CONFIRMATION ] (Hospital confirms units received & safely infused)
        │
        ▼
[ REQUEST COMPLETED ] (Lifecycle closed, audit logged, donor cooldown updated)
```

## 3. Platform Capabilities & Advanced Modules

### 🛡️ Role-Based Architecture (4 Distinct Portals)
1. **Voluntary Donor Portal**:
   - One-click availability switch: `AVAILABLE`, `AVAILABLE LATER`, `NOT AVAILABLE`.
   - Alert travel radius slider (1 - 150 km), quiet hours, and channel configuration (Push, SMS, Email).
   - Pre-donation 60-second medical safety screening quiz.
   - Gamification profile, donation streaks, and achievement badges (`FIRST_DROP`, `CENTURION_HERO`, etc.).
2. **Emergency Requester Portal**:
   - Streamlined 60-second emergency request creation.
   - Smart anti-duplicate warning to prevent duplicate broadcast flood.
   - Live stage-by-stage visual tracking timeline.
   - Post-fulfillment donor gratitude review and rating modal.
3. **Hospital Staff & Clinical Blood Bank Portal**:
   - Verification queue with clinical confirmation actions.
   - Clinical staff delegation roster (Chief Medical Officer, Attending Doctor, Triage Nurse, Lab Tech).
   - On-site blood reserve tracking with batch expiration warnings and emergency reservation lock.
   - Outbound HMS webhook integration signed with HMAC-SHA256.
4. **Administrative & Oversight Portal**:
   - Chained tamper-evident cryptographic audit ledger (`SHA-256` integrity verification).
   - Deep diagnostic health monitor (process memory, database query latency, socket count).
   - Tiered regional emergency broadcast dispatcher for multi-casualty incidents.
   - High-volume RFC 4180 streaming CSV report exporter with UTF-8 BOM.

## 6. Quick Start Guide

### Prerequisites
- Node.js 18+ and npm 9+
- Git

### Installation
```bash
# 1. Install root dependencies
npm install

# 2. Setup server
cd server
npm install
npx prisma generate
npx prisma db push
npm run seed

# 3. Setup client
cd ../client
npm install
```

### Running Locally
```bash
# Terminal 1: Backend Server (Port 5000)
cd server
npm run dev

# Terminal 2: Frontend Application (Port 5173)
cd client
npm run dev
```

Visit `http://localhost:5173` to explore the application.
